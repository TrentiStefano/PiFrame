WHY PIFRAME

Your Pi, in a desktop app

Four reasons Pi users try PiFrame, and why trying it costs nothing.

01 / PILLAR

Drop-in for Pi users. Zero risk to try.

PiFrame starts your installed pi and uses your existing config, providers, models, packages, skills and sessions. Nothing to migrate: sessions stay in Pi's own folder, so you can switch between the pi CLI and PiFrame at any time. PiFrame keeps its own data in ~/.piframe/ and changes files in ~/.pi/ only when you ask it to from the app (for example deleting a session or toggling an MCP server). Don't like it? Uninstall it: Pi is still there.

  • ✔ Works with your existing Pi sessions
  • ✔ Isolated data in ~/.piframe/
  • ✔ Uninstalling leaves Pi and your sessions in place
02 / PILLAR

Disconnect-safe.

Pi runs inside a local background service (pi-agentd), not inside the window. Close the window mid-turn and the agent keeps working. Reopen PiFrame and it reconnects and catches up on what happened, using a local log of the session's events.

  • ✔ Background daemon keeps workers alive
  • ✔ Session events logged locally
  • ✔ Automatic catch-up on window reconnect
03 / PILLAR

Local & private.

The background service listens only on 127.0.0.1 and requires a random per-install token. PiFrame has no analytics and no telemetry. Network traffic is what Pi sends to your model provider, plus the optional update check and remote access you choose to enable. Read security architecture →

  • ✔ Strict loopback binding (127.0.0.1)
  • ✔ Per-install cryptographic Bearer token
  • ✔ No analytics, no telemetry
04 / PILLAR

Native desktop app.

A real desktop app for Windows, macOS and Linux, with installers that bundle everything PiFrame needs (Pi itself stays your own install). Repository, chat and Git live in one window, with an integrated terminal for PowerShell, bash, zsh or WSL.

  • ✔ Installers for Windows, macOS and Linux
  • ✔ Native terminal: PowerShell, bash, zsh, and WSL
  • ✔ English and Italian UI

SYSTEM DESIGN

Decoupled Three-Tier Architecture

Three processes, each with one job. This is what makes the window optional and keeps Pi independent.

TIER 1 · FRONTEND

PiFrame Desktop GUI

The desktop app, built with Flutter for Windows, macOS and Linux and drawn by Impeller, Flutter's GPU renderer.

Flutter Desktop Impeller GPU Integrated Terminal
PCP, PiFrame's local protocol Localhost HTTP & WebSockets • Bearer Token • 127.0.0.1

TIER 2 · LOCAL DAEMON

pi-agentd Daemon

A local background service (a "daemon") that ships with PiFrame and its own Node runtime. It starts and supervises the Pi workers and logs their events to ~/.piframe/, so the window can close and reconnect.

Node Runtime Local Event Journal Session Reconnect
Pi RPC Stream pi --mode rpc • Bidirectional JSON over stdio

TIER 3 · CLI ENGINE

Pi Coding Agent Engine

Your own Pi installation (v0.85.0+), run as pi --mode rpc. Sessions stay in Pi's folder ~/.pi/agent/sessions/, readable by the pi CLI.

~/.pi/agent/sessions/ MCP Servers Model API Providers

The GUI is a Flutter desktop app; it talks to pi-agentd over PCP, PiFrame's local protocol (HTTP and WebSockets on 127.0.0.1 with a per-install token). Privacy details: Local & private and docs/security.md. Compatibility with the pi CLI: Drop-in for Pi users.

QUESTIONS & CLARIFICATIONS

Frequently Asked Questions

Does PiFrame collect telemetry or track my code? +

No. PiFrame and pi-agentd contain no analytics or telemetry. Details are in Local & private. See our security documentation.

How does disconnect-safety work when I close the app? +

PiFrame uses a decoupled architecture. When you start an agent action, the local daemon pi-agentd manages the session and appends stream events to a local journal in ~/.piframe/. If you quit the GUI window, restart your desktop shell, or lose connection, pi-agentd continues running. When you reopen PiFrame, it reads the journal sequence and reconciles state without duplicate actions.

Do I need to change my Pi setup? +

No. PiFrame is a drop-in companion. It launches your existing installed pi binary (pi --mode rpc), utilizing your existing Pi config, providers, models, extensions, skills, and sessions in ~/.pi/agent/sessions/. No migration or reconfiguration is needed.

What happens if I uninstall PiFrame? +

Removing PiFrame leaves Pi and your sessions in place. PiFrame keeps its own files in ~/.piframe/ (daemon tokens, journal cache, layout preferences), which the uninstaller leaves in place so you don't lose preferences. You can delete ~/.piframe/ manually at any time. Note: if you configured custom subagent context limits in Settings → Agents, reset them before uninstalling to ensure Pi settings don't reference helper files.

Do I need an API key for PiFrame? +

No separate key is needed for PiFrame. PiFrame does not ask for or store API keys. It uses whatever model providers and credentials you have already configured in the Pi CLI (via pi config or your environment variables).

Can I switch between the terminal Pi CLI and the PiFrame GUI? +

Yes. Sessions stay in Pi's own folder (~/.pi/agent/sessions/). You can start a task with pi in the terminal, open it in PiFrame to review the diff, and go back to the terminal.

Which operating systems are supported? +

PiFrame provides native installers for Windows 10/11 (x64), macOS Apple silicon, macOS Intel (x64), and Linux (Debian/Ubuntu x64). It also supports Windows Subsystem for Linux (WSL) repositories directly.

Can I use custom themes? +

Yes. PiFrame includes PiFrame Dark (#161c27) and PiFrame Light (#f1f3f7) default palettes. You can also import standard VS Code JSON theme files or place custom hot-reloadable JSON theme files into ~/.piframe/themes/.

Is PiFrame free? What is the license? +

Yes. PiFrame is free and open source under the MIT License. You can use it for personal and commercial work, read the code, and change it. The licenses of the third-party software in the installers are in THIRD_PARTY_NOTICES.md. Your model provider's usage terms and costs still apply.

Why is my Windows desktop window white or blank on launch? +

On Windows, PiFrame draws through Direct3D 11. In environments with virtual display drivers (such as USB Mobile Monitor, IddSampleDriver, Spacedesk, or secondary smartphone screen mirrors) or hybrid multi-GPU configurations, the Windows Desktop Window Manager swapchain can occasionally stall. A system reboot resolves the DirectX context state. You can also temporarily disable the virtual display adapter in Device Manager. See docs/troubleshooting.md for complete instructions.
