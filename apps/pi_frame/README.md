# pi_frame

The PiFrame Flutter app (Windows, macOS, Linux, and a web build for remote access). It is a client of the `pi-agentd` daemon in [`apps/agentd`](../agentd) and talks to it over PCP (HTTP + WebSocket on `127.0.0.1`). See the [repository README](../../README.md) for the product overview.

## Run

From the monorepo root, build the daemon first, then run the app:

```bash
pnpm build:agentd
cd apps/pi_frame
flutter run -d windows   # or macos / linux
```

`pnpm run:app:dev` does both from the root. For a web build served by the daemon: `flutter build web --no-web-resources-cdn`.

## Entry points

- `lib/main.dart`: the app (`runPiFrame`).
- `lib/main_harness.dart`: the off-screen harness build used by `pnpm harness` (see [`tools/harness/README.md`](../../tools/harness/README.md)). It enables harness mode and the extra VM-service hooks in `lib/harness/`.

## Source layout

| Folder | Contents |
| :--- | :--- |
| `lib/app/` | Shell, router (`go_router`), window chrome, focus regions |
| `lib/data/` | Riverpod providers and services: daemon client (`daemon/`), settings persisted under `~/.piframe/`, localized strings (`language/`), theme, terminal, updates |
| `lib/domain/` | Plain models: sessions, errors, updates |
| `lib/features/` | One folder per UI area: transcript, composer, sessions sidebar, workspace (repository, Git, editor), settings, side conversations, command palette and so on |
| `lib/ui/` | Shared widgets (`Frame*`), motion constants, code and diff blocks |

Design tokens (colors, spacing, typography, motion) come from [`packages/pi_frame_theme`](../../packages/pi_frame_theme); `test/theme_lint_test.dart` rejects hardcoded `Colors.*` or `Color(0x…)` in `lib/`. PCP types come from [`packages/pi_frame_protocol`](../../packages/pi_frame_protocol), generated by `pnpm codegen`.

User-facing text lives in `lib/data/language/strings_*.dart`, in both Italian and English.

## Checks

```bash
flutter analyze
flutter test
```

Some tests regenerate tracked screenshots under `docs/design-evidence` and `website/assets`; do not commit those changes (`git checkout -- docs/design-evidence website/assets`). Before a pull request, run `pnpm run verify` from the root ([docs/pr-verification.md](../../docs/pr-verification.md)).
