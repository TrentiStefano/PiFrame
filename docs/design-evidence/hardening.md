# Focused QA — context picker and sliders

Scope: this context-control iteration only. This report does not approve the whole application or advance Design Director beyond D9.

## Exercised

- Chat picker mounted before daemon connection: initial empty catalogue is retried on click; the menu opens and exact tier selection updates the chat chip.
- Older asynchronous initial catalogue cannot overwrite the successful click retry.
- Missing model metadata produces an explicit error instead of a silent click.
- Shared context selector: Custom / exact provider tiers / model maximum. Custom at the maximum remains Custom when reopened during the UI session.
- Custom maximum hidden for presets; selecting Custom snaps to the nearest bounded 50,000-token step. Slider range 100,000–1,000,000, reduced to the model's supported grid. Models below 100,000 cannot select Custom.
- Custom slider commits only on release. A failed request restores the accepted value and reports the error.
- Reserve slider range 0.5–25%, 0.5% steps. Legacy saved values outside that range are disclosed without silently rewriting preferences.
- Pending policy writes disable both controls, preventing overlapping max/reserve requests from the UI.
- Read-only, streaming and compaction-related busy states disable mutations.
- Usage meter uses runtime context tokens rather than cumulative session token totals.
- Existing composer drafts, send failures, navigation, state reducers and PCP serialization still pass their focused regression tests.
