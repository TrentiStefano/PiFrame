# Agent Instructions & Guidelines for PiFrame

## Strict Repository Rules

### 1. Real UI Captures Only
- **NEVER** invent, sketch, or code fake/simulated UI mockups in HTML/CSS/canvas when presenting the PiFrame application interface.
- **ALWAYS** use real screenshots, captures, or screen recordings from the actual Flutter application.
- Real UI captures are organized in:
  - `docs/design-evidence/recordly-projects/*.preview.png` (Real workspace runs, steer queue, reasoning streams, diff staging, theme editors)
  - `docs/design-evidence/bento-triptych-fixture-*.png`
  - `scratch/release_ui_screenshots/*.png`

### 2. Authentic Metrics & Data
- Do not fabricate false repository metrics (e.g. fake star counts, fake user counts).
- Present actual repository links, release targets, and verified feature capabilities.

### 3. MCP access:
- You have access and can use the Flutter or Dart MCP tools available in PiFrame environment.

### 4. Documentation
- When you implement a new feature, update docs/install.md to include the new feature
- When you fix a large or important bug, update docs/troubleshooting.md to include the new bug and the fix

### 5. Verification: `check` while working, `verify` before a PR
- **Inner loop: `pnpm run check`**, after every small change. It runs in the current working tree (no install, worktree or merge): the escape-hatch audit, TypeScript build and type checking for every package, and `flutter analyze` for the three Dart projects. Never add a lint suppression or type escape (`// ignore:`, `@ts-ignore`, `as any`, `: any`, ...) to make a check pass: the audit fails on any new one; fix the root cause instead (see `docs/pr-verification.md`). Pass test files to also run them: `pnpm run check -- apps/pi_frame/test/foo_test.dart tools/guardrails/test/steps.test.mjs` (`*_test.dart` runs with `flutter test`, `*.test.mjs|cjs|js` with `node --test`, and `<package>/src/**/*.test.ts` from its compiled `dist/**/*.test.js`).
- **Full gate: `pnpm run verify`**, before any pull request (or push to `main`). Commit first: it checks the committed HEAD merged with `origin/main` in a throw-away worktree, with the same steps as `ci.yml`. Add `-- --release` before a release (web and desktop builds) and `-- --e2e` for the emulated-iPhone remote web test. `release.yml` runs only after the merge and burns runner minutes when it fails.
- To open the PR use `pnpm run pr`: it runs `verify`, and only if it passes pushes the branch and runs `gh pr create`.
- Do not commit screenshots regenerated by tests (`docs/design-evidence`, `website/assets`); restore them with `git checkout -- <path>`.
- Details, options and limits: `docs/pr-verification.md`.
