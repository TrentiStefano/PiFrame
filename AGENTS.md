# Agent Instructions & Guidelines for PiFrame

## Strict Repository Rules

### 1. Real UI Captures Only
- **NEVER** invent, sketch, or code fake/simulated UI mockups in HTML/CSS/canvas when presenting the PiFrame application interface.
- **ALWAYS** use real screenshots, captures, or screen recordings from the actual Flutter application.
- Real UI captures are organized in:
  - `docs/design-evidence/recordly-projects/*.preview.png` (Real workspace runs, steer queue, reasoning streams, diff staging, theme editors)
  - `docs/design-evidence/bento-triptych-fixture-*.png`
  - `scratch/release_ui_screenshots/*.png`

### 2. Authentic Metrics & Data
- Do not fabricate false repository metrics (e.g. fake star counts, fake user counts).
- Present actual repository links, release targets, and verified feature capabilities.

### 3. MCP access:
- You have access and can use the Flutter or Dart MCP tools available in PiFrame environment.

### 4. Documentation
- When you implement a new feature, update docs/install.md to include the new feature
- When you fix a large or important bug, update docs/troubleshooting.md to include the new bug and the fix
